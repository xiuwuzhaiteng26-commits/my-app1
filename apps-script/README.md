# 年収の壁・労働時間管理ツール

複数のアルバイトを掛け持ちしている昼間学生向けに、

1. 年間の税金・社会保険の壁（123万円 / 130万円 / 150万円）までの残り
2. 勤務先ごとの月間労働時間が「4分の3基準」に近づいていないか

を毎日自動でチェックするツールです。

Google カレンダーに書いたシフトを毎日 23:30 に読み取り、Google スプレッドシートに
積み上げて集計します。

確認は**スマホアプリの画面**から行えます。Apps Script の「ウェブアプリ」として公開すると
専用の URL ができるので、スマホのホーム画面に追加すればアプリのように使えます
（壁までの残り、当月の労働時間、月次の答え合わせ、勤務先ごとの上限設定まで画面から操作できます）。
スプレッドシートを直接開いて確認・編集することもできます。

**金額はすべて額面（源泉徴収前の総支給額）で計算します。** 手取り額は計算対象外です。
源泉徴収された分は確定申告で還付される前払いに過ぎず、監視対象は「壁の基準を満たすか
どうか」であって、手元に残る金額ではないためです。

> **免責**：本ツールの金額・時間の壁は目安であり、正式な判断は税務署・年金事務所・
> 各勤務先の労務担当に確認してください。

---

## なぜ Google Apps Script なのか

「毎日 23:30 に自動実行」「Google カレンダーを読む」「Google スプレッドシートに書く」を
満たすには、常時起動のサーバーも API キーの管理も要らない Google Apps Script が一番
手間がかかりません。カレンダーとスプレッドシートに同じ Google アカウントでそのまま
アクセスできます。アプリ画面もウェブアプリとして同じプロジェクトから公開できるので、
ログインやアクセス制限を自分で作る必要もありません。

## セットアップ手順

### 1. スプレッドシートを作る

1. https://sheets.new で新しいスプレッドシートを作る
2. 名前を「年収の壁管理」などに変更する

### 2. スクリプトを貼り付ける

#### 方法A：全部入り1ファイルを貼る（おすすめ・コピペ1回）

1. スプレッドシートのメニューから **拡張機能 → Apps Script** を開く
2. 左上のプロジェクト名を「年収の壁ツール」などに変更する
3. **プロジェクトの設定**（左の歯車 / Project Settings）→ タイムゾーン（Time zone）を
   **(GMT+09:00) 東京 / Tokyo** にする ← ここがずれていると23:30の自動実行が別の時刻になります
   （ずれている場合は初期セットアップ時に警告が出ます）
4. エディタに戻り、既定の `コード.gs` の中身を**すべて削除**する
5. [`dist/all-in-one.gs`](dist/all-in-one.gs) の中身をすべてコピーして貼り付ける
   （GitHub の画面右上のコピーボタンで全文コピーできます）
6. 保存する

これだけで、画面（HTML）も含めた全機能が入ります。

#### 方法B：ファイルを分けて貼る（コードをいじりたい人向け）

1. 既定の `コード.gs` を削除する
2. 以下のファイルを、Apps Script エディタに同じ名前で1つずつ作って貼り付ける
   （拡張子 `.js` の部分はエディタ上では `.gs` になります）

   | このリポジトリのファイル | Apps Script 側のファイル | 役割 |
   | --- | --- | --- |
   | `Config.js` | `Config.gs` | 設定（壁の金額・上限時間・通知先） |
   | `Html.js` | `Html.gs` | 画面ファイルの読み込み |
   | `Util.js` | `Util.gs` | 日付・数値の小さな部品 |
   | `Sheets.js` | `Sheets.gs` | シートの定義と読み書き |
   | `Parser.js` | `Parser.gs` | 予定タイトルの解析 |
   | `Calc.js` | `Calc.gs` | 実働時間・収入・壁・所得の計算 |
   | `CalendarSource.js` | `CalendarSource.gs` | カレンダーからの取り込み |
   | `Summary.js` | `Summary.gs` | サマリーシートと通知本文 |
   | `Notify.js` | `Notify.gs` | 通知の送信 |
   | `Reconcile.js` | `Reconcile.gs` | 月次の答え合わせ |
   | `Reconcile.html` | `Reconcile.html` | 答え合わせの入力画面 |
   | `WebApp.js` | `WebApp.gs` | スマホアプリ画面のデータと操作 |
   | `App.html` | `App.html` | スマホアプリ画面 |
   | `Main.js` | `Main.gs` | メニュー・毎日の実行・トリガー |
   | `Tests.js` | `Tests.gs` | セルフテスト |
   | `appsscript.json` | マニフェスト | タイムゾーンと権限 |

   `appsscript.json` は「プロジェクトの設定 → 『appsscript.json』マニフェスト ファイルを
   エディタで表示する」にチェックを入れると編集できます。

3. 保存する

`dist/all-in-one.gs` は `apps-script/` の各ファイルから自動生成しています。
コードを直したら `npm run build:apps-script` で作り直してください
（`npm run test:apps-script` を実行すると自動で作り直し、1ファイル版に対しても
同じテストを流します）。

> `clasp` を使う場合は `apps-script/` ディレクトリで `clasp clone <scriptId>` または
> `clasp create --type sheets` して `clasp push` するだけです（`.clasp.json.example` 参照）。

### 3. 初期セットアップを実行する

1. スプレッドシートを開き直す（メニュー **「年収の壁ツール」** が出ます）
2. **年収の壁ツール → ① 初期セットアップ（シート作成）** を実行
3. 初回のみ Google の権限確認が出ます。「詳細」→「（プロジェクト名）に移動」→「許可」
   （カレンダーの読み取り・スプレッドシートの編集・メール送信の権限を求めます）
4. 必要なシートと、壁の初期値（123万円 / 130万円 / 150万円）が作られます

### 4. 毎日 23:30 の自動実行を設定する

**年収の壁ツール → ② 毎日23:30のトリガーを設定** を実行します。

> Google の仕様上、時間指定トリガーの実行時刻は指定時刻を含む1時間枠の中で前後します
> （23:30 指定なら概ね 23:15〜23:45）。その日の 0:00〜23:59 の予定を読むので、
> 多少ずれても集計内容は変わりません。

**アプリを開いた時点で、直近1ヶ月分をその場で取り込みます**（`CONFIG.app.autoImportDays`）。
毎晩23:30を待たなくても、カレンダーに書いた予定はアプリを開けばすぐ反映されます。
毎晩の実行でも同じく**直近1ヶ月分を見直します**（`CONFIG.daily.lookbackDays`）。

内容が変わっていない行はシートに書き込まないので、1ヶ月分を毎回見直しても遅くなりません
（予定を直した場合だけ、その行が書き直されます）。取り込みは上書きなので、
何度見直しても二重計上にはなりません。
1ヶ月より前の予定を足した場合だけ、「期間を指定して取り込み直す」を使ってください。

### 5. アプリとして公開する

1. Apps Script エディタの右上 **デプロイ → 新しいデプロイ**
2. 歯車アイコン → 種類の選択で **ウェブアプリ**
3. 設定を次のようにする
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **自分のみ**（収入情報を扱うので必ずこれにしてください）
4. **デプロイ** を押すと `https://script.google.com/macros/s/.../exec` という URL が出ます
5. スマホでその URL を開き、ブラウザのメニューから **「ホーム画面に追加」** を選ぶと
   アイコンから起動できるようになります

URL は後から **年収の壁ツール → ③ アプリのURLを表示** でいつでも確認できます。

> コードを更新したときは、**デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン「新バージョン」
> → デプロイ** で反映します。URL は変わりません。

### 6. 過去の分をまとめて取り込む（任意）

**年収の壁ツール → 期間を指定して取り込み直す** で、開始日と終了日を `yyyy-MM-dd` で
指定すると過去のカレンダーもまとめて取り込めます（一度に最大400日）。
同じ予定を何度取り込んでも重複しません。

## アプリの画面

下部のタブで4つの画面を切り替えます。

| タブ | できること |
| --- | --- |
| **ホーム** | 年間収入（額面）、壁ごとの残りと進捗バー、今月の勤務先ごとの労働時間と進捗、直近の勤務一覧 |
| **収入** | 年間収入の内訳、合計所得金額（控除・経費を引いた額）、カレンダー外の収入の登録 |
| **照合** | 月次の答え合わせ。対象月と勤務先を選ぶと推定額が出るので、給与明細の実額を入れて差分を確認 |
| **見込み** | この先1ヶ月の予定を先読みした月間労働時間と壁の見込み、勤務調整のアドバイス |
| **設定** | 勤務先ごとの月間上限の変更（暫定→実数）、手動での取り込み、スプレッドシートへのリンク |

右上の「更新」で最新の状態に読み直します。壁と労働時間は状態に応じて
緑（正常）・オレンジ（注意）・赤（警告）で色分けされます。免責は全画面の下部に常時表示されます。

日々の操作は「カレンダーに予定を書く」だけで、集計は毎晩23:30に自動で走ります。
アプリは**確認と、月1回の答え合わせのため**に開くものです。

## カレンダーの書き方

予定のタイトルを次の形式で入力します。

```
[会社名] 開始時刻-終了時刻 休憩Xh 時給Y円
```

例：

```
[Kakedas] 09:00-18:00 休憩1h 時給1226円
[バイトレ] 13:00-17:00 休憩なし 時給1700円
```

ルール：

- 会社名は `[ ]` で囲む（**これがある予定だけを勤務予定として扱います**。囲みの無い予定は
  完全に無視するので、授業やプライベートの予定が混ざっていて構いません）
- 休憩が無い場合は「休憩なし」と明記する
- 時給は末尾に「円」を付ける
- **読むのはタイトルだけ**です。説明欄・場所欄には何を書いても影響しません

### 時刻を省く書き方（おすすめ）

カレンダーの予定そのものに開始・終了時刻を設定してあるなら、**タイトルの時刻は省けます**。

```
[Kakedas] 休憩1h 時給1226円      ← 予定を 9:00〜18:00 に設定しておく
```

この場合は予定の時刻がそのまま実働の計算に使われます。時間を変更したいときは
カレンダー上で予定をドラッグするだけで済むので、こちらの方が楽です。

タイトルに時刻を書いた場合は、**タイトルの方が優先**されます（予定の枠は1時間のまま、
実際は9〜18時、という書き方もできます）。

以下の表記ゆれは自動で吸収します：

- 全角（`［Ｋａｋｅｄａｓ］ ０９：００−１８：００ 休憩１ｈ 時給１，２２６円`）
- 時刻の区切り（`-` `〜` `~` `–` `ー`）
- 休憩の書き方（`休憩1h` `休憩1.5h` `休憩1時間30分` `休憩90分` `休憩なし`）
- 日をまたぐ勤務（`22:00-06:00` は翌6時までとして計算）

フォーマットが崩れていて計算できない予定は、サマリーシートの「注意メッセージ」欄に
理由付きで表示されます（黙って無視はしません）。

## 複数アカウントのカレンダーをまとめる

バイトの予定を別のGoogleアカウント（学校用・プライベート用など）のカレンダーに
書いている場合、そのカレンダーを**共有**すれば、このツールを実行しているアカウント
からも読めるようになります。

### 手順（共有したい側のアカウントで行う）

1. 共有したいカレンダーを持つアカウントで、ブラウザで
   [Google カレンダー](https://calendar.google.com) を開く
2. 左側の「マイカレンダー」から、共有したいカレンダー名の上にマウスを乗せて
   **⋮（その他の操作） → 設定と共有**
3. 「特定のユーザーとの共有」→ **ユーザーを追加**
4. **ツールを実行しているアカウントのメールアドレス**を入力
5. 権限は **「予定の詳細をすべて表示」** を選ぶ（読み取りだけで十分。
   「変更を加える」権限は不要です）
6. **送信**

これで、ツールを実行しているアカウント側の Google カレンダーを開くと、左側の
「他のカレンダー」欄にそのカレンダーが増えます（表示されない場合は、共有された側の
アカウントで届く招待メールの承認が必要な場合があります）。

### カレンダーIDの調べ方

1. ツールを実行しているアカウントで Google カレンダーを開く
2. 「他のカレンダー」に増えたカレンダーの上にマウスを乗せて
   **⋮ → 設定と共有**
3. 少し下にある **「カレンダーの統合」** の欄に **「カレンダー ID」** が表示される
   （多くの場合、共有した側のGoogleアカウントのメールアドレスと同じ形です）

### 設定への追加

`Config.js`（または `dist/all-in-one.gs`）の `calendarIds` に、調べたIDを追記します。

```js
calendarIds: ['primary', 'その他アカウントのカレンダーID', 'もう一つのアカウントのカレンダーID'],
```

`'primary'` は実行アカウント自身のカレンダーなので、これは残したままにしてください。
保存して次に取り込みを実行すると、追加したカレンダーの予定もまとめて読み込まれます
（毎晩の実行・アプリを開いたときの自動取り込み・見込みの先読み、すべてで有効です）。

### 注意点

- 読み取るのは**タイトルが `[会社名] …` の形式の予定だけ**です。それ以外の予定
  （プライベートの用事など）が共有カレンダーに混ざっていても無視されます
- カレンダーが共有されていない・IDを間違えている場合は、取り込みを止めずに
  サマリーシートの「注意メッセージ」にエラーとして表示されます
- 同じ日・同じ勤務先・同じ開始時刻の予定が複数のカレンダーに重複して存在すると、
  それぞれ別の勤務として二重に計上されます。同じシフトを2つのカレンダーに
  書かないよう注意してください

## シート構成

| シート | 内容 |
| --- | --- |
| **サマリー** | 集計結果。普段見るのはここだけで済みます |
| **勤務明細** | カレンダーから取り込んだ勤務の明細 |
| **手入力の収入** | カレンダー化されていない収入（業務委託分など）の手入力 |
| **勤務先の上限** | 勤務先ごとの月間労働時間の上限 |
| **壁の設定** | 壁の金額（123万円 / 130万円 / 150万円） |
| **月次の答え合わせ** | 給与明細との差分 |
| `実行ログ` | 毎日の実行結果の履歴（直近500件） |

### 勤務明細

ID / 日付 / 勤務先 / 開始 / 終了 / 休憩(h) / 実働(h)（自動計算） / 時給(円) /
推定収入(円)（自動計算） / 照合済み / 元の予定タイトル / 更新日時

- 「ID」はカレンダーの予定 ID ＋ 日付です。これをキーに上書きするので、再取り込みしても
  重複しません（繰り返し予定にも対応）。
- 「照合済み」は再取り込みしても消えません。
- 「実働(h)」は表示のため小数第2位に丸めていますが、「推定収入」は
  丸める前の実働分数で計算しています。

> 列の見出しは日本語ですが、処理は列の位置で行っています。**列の順番を入れ替えたり
> 挿入したりしないでください**（見出しの文字を変えるだけなら影響ありません）。

### 手入力の収入

ID / 収入元 / 区分（給与所得 / 事業所得 / 雑所得） / 対象期間 / 金額(円) /
必要経費(円) / メモ / 更新日時

3〜5月の業務委託分など、カレンダーに無い過去の収入をここに固定値で登録します。
**年収の壁ツール → 手入力の収入を追加** から入力するか、シートに直接書いても構いません。

- 「対象期間」は `2026-03` や `2026-03〜2026-05` のように、**年が分かる形**で書いてください
  （年が読み取れない行は集計から外し、サマリーに警告を出します）
- 「必要経費」は事業所得・雑所得のものです（給与所得なら 0）

### 勤務先の上限

勤務先 / 月間上限(h) / 確定 / メモ / 更新日時 / 週の上限(h) / 連続月数 / 根拠

新しい勤務先がカレンダーに現れると、暫定値 **120時間**・`confirmed = FALSE` で自動登録
されます。正社員の所定労働時間の正式な回答が来たら、**アプリの「設定」タブで実数に
書き換えて「会社から正式な回答をもらった」にチェック**を入れてください
（シートを直接編集しても同じです。会社ごとに別の値を持てます）。

会社によって基準の示され方が違うので、3種類の書き方に対応しています。

| 会社の言い方 | 入れる値 |
| --- | --- |
| 「正社員は週40時間。その4分の3が基準」 | **週の上限** に `30`（月間上限には目安として `130`） |
| 「月◯時間まで」 | **月間上限** に その時間 |
| 「月◯時間以上が2ヶ月連続で対象」 | **月間上限** に その時間、**連続月数** に `2` |

- **週の上限** … 月曜〜日曜の週ごとに判定します。空欄なら週の判定はしません
- **連続月数** … `2` 以上にすると「その月数だけ連続で月間上限に達したら警告」になります。
  先月だけ超えている状態では「今月はあと◯時間で連続になる」と注意が出ます。通常は `1`
- **根拠** … 会社から何と言われたかを残しておく欄です（判定には使いません）
暫定値のままの勤務先はサマリーに「（上限は暫定値）」と表示されます。

### 壁の設定

壁の名前 / 金額(円) / 適用年 / 最終更新日 / 備考

年度が変わって金額が変わったら、**このシートの値と「最終更新日」を書き換えるだけ**です
（コード側にはハードコードしていません）。「適用年」が集計対象年と一致する行だけが
判定に使われるので、翌年分の行を足しておくこともできます。

初期状態では3つの壁が入りますが、**それぞれ「誰の」「何の」壁かが違います**。

| 壁 | 誰の壁か | 何が起きるか |
| --- | --- | --- |
| **123万円** | 学生本人の所得税 | 超えると本人が所得税を払うことになる |
| **130万円** | 学生本人の社会保険 | 超えると親の健康保険の扶養から外れ、自分で健康保険・年金に入る必要が出る（勤務先の規模によっては106万円が基準になる場合がある） |
| **150万円** | **親の**税金（特定親族特別控除） | 超えても即ゼロにはならないが、188万円まで段階的に親の控除（63万円）が減っていく。2025年度税制改正で新設（19〜22歳の子が対象） |

**130万円と150万円は制度自体が別物です。** 130万円は「学生本人の社会保険」、150万円は
「親の税金の控除」の話なので、どちらか一方だけ気にすれば良いわけではありません。
親が扶養控除を使っていない場合（世帯の状況によります）は、150万円の壁は該当しない
こともあります。実際に該当するかは、親の勤務先の年末調整担当や税務署に確認してください。

CONFIG.js の `walls.thresholds` を書き換えて壁を追加・変更した場合、初期セットアップを
再実行すると、**まだ「壁の設定」シートに無い名前の壁だけ**が追加されます（シート上で
自分が編集した既存の壁の内容は上書きされません）。

---

> 以前のバージョンで英語名（`calendar_income_entries` など）のシートを作っていた場合は、
> 初期セットアップを実行すると**中身をそのまま引き継いで日本語名に付け替え**、
> 1行目の見出しも日本語に貼り替えます。

## 集計の中身

- **実働時間** = (終了時刻 − 開始時刻) − 休憩時間
- **その日の推定収入（額面）** = 実働時間 × 時給
- **年間収入合計（壁の判定に使う額）** = 給与収入（カレンダー＋手入力）＋ 事業収入 ＋ 雑収入
- **合計所得金額**（収入額そのものとは別の数値。税金の壁の判定に使う）
  = (給与収入 − 給与所得控除 65万円) ＋ (事業収入 − 必要経費) ＋ (雑収入 − 必要経費)
  ※ それぞれ 0 未満にはしません

### 警告の出方

| 対象 | 注意 | 警告 |
| --- | --- | --- |
| 勤務先ごとの月間実働時間 | 上限の 80%（暫定 96時間） | 上限の 100%（暫定 120時間） |
| 勤務先ごとの週間実働時間（週の上限がある場合） | 上限の 80% | 上限の 100% |
| 連続月（連続月数が2以上の場合） | 先月まで連続で上限到達 | 指定月数だけ連続で上限到達 |
| 年間の壁 | 壁の 90% | 壁を超過 |

割合はすべて `Config.js` で変更できます。

## 過去のデータをまとめて入れる

カレンダーに入っていない過去の収入・シフトは、`SeedData.js` の2つの配列に書いて
**年収の壁ツール → 実データを取り込む（初回のみ）** を実行すると一括で登録できます。

```js
var SEED_MANUAL_INCOME = [
  {
    source_name: '〇〇株式会社',
    income_category: '給与所得',   // 給与所得 / 事業所得 / 雑所得
    period: '2026-03〜2026-05',    // 年が分かる形で
    amount: 100000,               // 額面（円）
    expenses: 0,                  // 必要経費（円）。給与所得なら0
    note: '3月分〜5月分'
  }
];

var SEED_SHIFTS = [
  // [日付, 勤務先, 開始, 終了, 休憩(h), 時給(円)]
  ['2026-06-10', '〇〇', '09:00', '18:00', 1, 1200]
];
```

- **何度実行しても二重計上しません**（収入は「収入元＋対象期間」、シフトは
  「日付＋勤務先＋開始時刻」をキーに上書きします）
- 同じ勤務が**カレンダーからも取り込まれた場合はカレンダー側を正**とし、
  手入力側の行は自動で取り除きます
- 手入力の収入は金額だけなので、**労働時間の警告（4分の3基準）には反映されません**。
  時間も管理したい勤務先は、カレンダーに書くか `SEED_SHIFTS` に入れてください

> **この配列は公開リポジトリでは空にしてあります。** 収入額・勤務先名は個人情報なので、
> 自分の Apps Script プロジェクト側でだけ中身を書いてください。
> リポジトリが公開設定の場合、コミットすると履歴に残り続けます。

## この先の見込みと勤務調整のアドバイス

過去の実績を見るだけでなく、**カレンダーに入っている先の予定を読んで、超える前に知らせます**
（既定で35日先まで。`CONFIG.forecast.lookaheadDays`）。

- **月間労働時間の見込み** … 会社ごとに「実績＋これからの予定＝見込み」を出し、
  上限の80%で注意・100%で警告
- **壁の見込み** … 予定を全部こなした場合の年間収入で、123万円・130万円までの残りを判定
- **年末の着地** … 直近3ヶ月の平均月収から年末の見込みを試算し、
  壁に到達しそうな月を出す（あくまで目安。カレンダー分のみで計算）

超えるときは、**何をどれだけ減らせばいいかまで出します**。

```
【2026-08】Kakedas は見込み 128時間で、上限 120時間を 8時間超えます。
8/25(火) 8時間 を外すと 120時間になり収まります。

予定を全部こなすと 123万円の壁を 52,000円 超えます。
平均時給1,226円なら 43時間分（8時間勤務で約6日分）減らす必要があります。
```

余裕があるときも、あとどれだけ働けるかを出します。

```
予定を全部こなしても 123万円まで 649,246円 余裕があります。
平均時給1,226円なら あと529時間（8時間勤務で約66日）働けます。
```

外すシフトは**件数が少なくて済むよう長いシフトから選びます**。
先読みした予定は**勤務明細には書き込みません**（実績と見込みを混ぜないため）。
すでに取り込み済みの勤務は予定から除くので、二重には数えません。

見込みはアプリの **📅見込み** タブ、サマリーシート、毎晩のメールの3か所に出ます。

## 月次の答え合わせ

月に1回、実際の給与明細・支給照会の合計額を入れて、カレンダー推定額とのズレを確認します。

- **アプリから**：「照合」タブ。対象月と勤務先を選ぶと推定額が表示されるので、
  実額を入れて保存すると差分が出ます。
- **PC から**：**年収の壁ツール → 月次の答え合わせを入力**（同じ内容のダイアログ）。
- **スマホから**：**月次の答え合わせ** シートに「年月」（`2026-08` 形式）・
  「勤務先」・「実際の支給額」を直接書くだけです。推定額と差分はその日の23:30の自動実行時に
  計算されます（すぐ見たい場合は **年収の壁ツール → 月次の答え合わせを再計算**）。

差分が「推定額の5%超」かつ「3,000円超」の両方に当てはまると `要確認` になります
（少額のときに率だけで騒がないようにするため）。この基準も `Config.js` の
`reconcile` で変えられます。勤務先に `合計（全勤務先）` を選ぶと全社合計で照合できます。
照合した月の明細には `reconciled` フラグが立ちます。

## 通知

既定は **`email`** です。毎日 23:30 の実行後に、その日の勤務内容・壁までの残り・
当月の労働時間をまとめたメールが、スクリプトを実行している Google アカウントの Gmail に
届きます（`emailTo` を書けば別のアドレスにも送れます）。

`Config.js` の `notify` で変更できます。

```js
notify: {
  channel: 'email',        // 'sheet' | 'email' | 'webhook'
  emailTo: '',             // 空なら実行アカウントのGmail宛
  alwaysNotifyOnAlert: false, // 'sheet' でも注意・警告の日だけメールするなら true
  webhookUrl: '',          // Slack / Discord の Incoming Webhook URL
  webhookFormat: 'slack'   // 'slack' | 'discord' | 'json'
}
```

- 毎日のメールが多いと感じたら `channel: 'sheet'` ＋ `alwaysNotifyOnAlert: true` にすると、
  注意・警告が出た日だけメールが届くようになります。
- `channel: 'sheet'` にすると外部への送信は一切行いません。

どの設定でも、実行結果は必ずサマリーシートと `実行ログ` シートに残ります。

## 表示が速い理由（内部の作り）

Apps Script はスプレッドシートやカレンダーへのアクセス1回ごとに待ち時間が発生し、
これが体感速度をほぼ決めます。アプリを開いたときの往復回数を減らすため、
次の3つを行っています。

- **同じ表は1回しか読まない** … 1回の実行の中で読み込み結果を覚えておきます。
  書き込みを行った表は必ず捨てて読み直すので、古い値が表示されることはありません
- **カレンダーは1回でまとめて読む** … 「過去1ヶ月の取り込み」と「先1ヶ月の見込み」で
  別々に読むのではなく、両方を含む期間を最初に1回だけ取得します
- **移行処理は済んだらやらない** … シート名の付け替えや見出しの貼り直しは、
  一度終わったらスクリプトプロパティに記録して次回から省きます
  （`SCHEMA_VERSION` を上げたときと、メニューの「① 初期セットアップ」を
  実行したときだけやり直します）

これによりアプリを開いたときの往復は **26回から4回** に減っています。
この回数は結合テストで見張っていて、増えるとテストが落ちます。

## テスト

```bash
npm run test:apps-script
```

3種類のテストが動きます。

- **セルフテスト**（`tests/run-node-tests.mjs`）… タイトル解析・実働時間・給与所得控除・
  壁の判定・労働時間の警告など、Google のサービスに依存しない計算ロジック
- **結合テスト**（`tests/run-integration-tests.mjs`）… `SpreadsheetApp` / `CalendarApp` を
  テスト用の偽実装に差し替えて、取り込み → シート書き込み → サマリー生成 →
  月次の答え合わせ → アプリ画面のデータ取得までを通しで実行
- **1ファイル版の結合テスト**（`--bundle`）… 生成した `dist/all-in-one.gs` に対して
  同じ結合テストを流し、貼り付け用のファイルが単体で動くことを確認
- **画面テスト**（`tests/run-page-tests.mjs`）… `doGet` が返すHTMLからスクリプトを取り出し、
  最小限のDOMの偽物の上で実際に実行する。「サーバー側は正しいのに画面が読み込み中のまま
  固まる」種類の不具合を捕まえる

Apps Script 側からは **年収の壁ツール → セルフテストを実行** でセルフテストを実行できます
（`tests/` は Apps Script には貼り付け不要です）。

## Google の表示言語が英語の場合

Google アカウントの言語設定が日本語以外だと、スプレッドシートや Apps Script の
メニューが英語（File / Extensions / Deploy …）になります。ツールのメニュー
「年収の壁ツール」と画面は日本語のままで、動作にも影響はありません。

ただし**タイムゾーンだけは必ず確認**してください。ロケールが日本以外だと
米国時間などになっていることがあり、毎日23:30の自動実行が日本時間の別の時刻に動きます。

| 確認する場所 | 英語表示 | 設定する値 |
| --- | --- | --- |
| Apps Script | Project Settings → Time zone | (GMT+09:00) Tokyo |
| スプレッドシート | File → Settings → Time zone / Locale | (GMT+09:00) Tokyo / Japan |

ずれている場合、初期セットアップとトリガー設定のときに警告が出て処理が止まります。
サマリーシートの「注意メッセージ」にも表示されます。

日本語表示に戻したいときは https://myaccount.google.com/language で日本語を先頭にしてください。

主なメニューの対応:

| 日本語 | 英語 |
| --- | --- |
| 拡張機能 → Apps Script | Extensions → Apps Script |
| デプロイ → 新しいデプロイ | Deploy → New deployment |
| ウェブアプリ | Web app |
| 次のユーザーとして実行: 自分 | Execute as: Me |
| アクセスできるユーザー: 自分のみ | Who has access: Only myself |
| ファイル → 設定 | File → Settings |

## 年度が変わったら

1. **壁の設定** シートに新年度の行を追加（または金額と「最終更新日」を更新）
2. `Config.js` の `salaryDeduction`（給与所得控除）と `configLastUpdated` を確認・更新
3. 給与所得控除・扶養控除の要件は毎年変わり得ます。必ず最新の情報を確認してください
